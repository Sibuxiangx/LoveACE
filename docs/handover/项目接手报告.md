## 3. 领域与网络拓扑

LoveACE 是安徽财经大学（AUFE）的校园工具箱。所有业务都建立在**深信服 EasyConnect VPN + 统一身份认证（UAAP/CAS）**之上。

### 3.1 两段式登录（三端同构）

```text
① EC/VPN 登录  https://vpn2.aufe.edu.cn
   GET  /por/login_auth.csp?apiversion=1
        → 解析 <TwfID> <RSA_ENCRYPT_KEY> <RSA_ENCRYPT_EXP> <CSRF_RAND_CODE>
   POST /por/login_psw.csp?anti_replay=1&encrypt=1&type=cs
        密码 = RSA_PKCS1("$ecPassword_$csrfCode", modulus, exp) → hex
        响应含 <Result>1</Result> 即成功；"maybe attacked" 表示触发风控
   → 手动把 TWFID cookie 写入 cookie jar

② UAAP/CAS 登录
   GET  http://uaap-aufe-edu-cn.vpn2.aufe.edu.cn:8118/cas/login?service=...jwcxk2...
        → 解析 lt / execution
   POST 同上，密码 = 3DES_ECB_PKCS7(password, key=lt 前 8 字节重复 3 次) → Base64
   → 响应 URL 含 jwcxk2 或 ticket= 即成功
```

- 加密实现：Android `org.bouncycastle`（[AUFEConnection.kt](../../android/app/src/main/java/tech/loveace/appv3/data/network/AUFEConnection.kt)）；iOS 走 `Security`/`CommonCrypto`（[AUFEConnection.swift](../../ios/loveaceios/Network/AUFEConnection.swift)）；桌面用 `pointycastle`（[connector.dart](../../desktop/lib/services/aufe/connector.dart)）。
- **TWFID 是整条链路的命门**：三个 HttpClient（普通 / simple / noRedirect）各自持有 cookie jar，登录后靠 `copyCookiesFrom` 手工同步。新增 client 时忘记 copy 是最常见的「登录成功但请求 302」原因。
- 会话保活：三端都是**每 4 分钟**心跳一次 `login_auth.csp`，看响应里是否还有 `<TwfID>`。过期后自动用已保存的凭证重连（Android/iOS/桌面各自实现）。

### 3.3 解析方式与各系统脆弱点

- 教务成绩/考试多数是 JSON（`Json.parseToJsonElement`），但**分数记录是位置数组**（`arr[0]` 学号…`arr[10]` 分数），字段一旦增删就整体错位。
- 学期列表、座位号、部分课表是 **Jsoup/SwiftSoup DOM 解析**；也有不少正则，例如动态路径 `/([A-Za-z0-9]+)/allTermScores/data`（[JWCService.kt:109](../../android/app/src/main/java/tech/loveace/appv3/data/service/JWCService.kt)）。
- 上游改版时会**静默返回空列表**（异常被 catch 成 failure，UI 显示"暂无数据"），这是排查"功能突然没数据"的第一嫌疑。

| 系统 | 脆弱点 |
| --- | --- |
| JWC 成绩 | 先 GET 首页抓动态路径（路径与 cookie 绑定），再 POST 取数；路径正则失配即全挂 |
| JWC 考试 | 日期范围用「学期代码末位 1 → 次年 3/30，否则当年 9/30」的启发式；座位号只按课程名匹配，同名课会串 |
| 培养方案 | 从 `<script>` 里正则抓 zTree JSON；若解析出「0 通过」，会**再拉全部学期成绩逐条比对**，非常慢（3 秒最小请求间隔 + 5 分钟缓存） |
| YKT 流水 | 8 列 `<td>` 正则 + 去标签，查询超时设为 600s 且不重试 |
| 电费充值 | 金额/房间表单靠字段拼接，`pay()` 只尝试一次，超时可能既没结果也没回滚 |
| 竞赛 | ASP.NET WebForms，必须带 `__VIEWSTATE/__EVENTVALIDATION` postback 分页；裸 IP 域名（`211-86-241-245.vpn2...`） |
| 报修 | PHP session 靠访问 `/index.php/index/user` 触发；`ensureSession()` 失败也会标记成功（见 6.4-4）；上游路径 typo `staue` 被保留 |
| ISIM | 从 `/go` 拿 `JSESSIONID` 后手动拼 Cookie；三端初始化 URL 都写成 `sn=sn`，取到的 `twfId` 未使用（疑似笔误，改前先抓包确认服务端是否忽略该参数） |
| 门卡 | 第三方 `spoyn.cn`，不依赖 VPN；登录参数在 URL query（见 P0-2） |

## 4. 三端结构

### 4.1 Android（`android/`，单模块 `:app`）

**构建**（[app/build.gradle.kts](../../android/app/build.gradle.kts)）

- `applicationId = tech.loveace.appv3`，`minSdk 26` / `targetSdk 36` / `compileSdk 36`，AGP 9.0.1，Kotlin 2.0.21，Compose BOM 2025.07.00，`material3 1.5.0-alpha14`（Expressive），Glance 1.1.1。
- `versionName 1.1.21`、`versionCode 10121`，规则 `major*10000 + minor*100 + patch`，**CI 会校验输入版本与 Gradle 完全一致**。
- 签名：只有存在 4 个 `ANDROID_*` 环境变量时才创建 release signingConfig，否则打 debug 签名包（CI 通过 base64 secret 落盘 `app/loveace-release.jks`）。
- `isMinifyEnabled = false` —— 包体未优化，也没有 R8 带来的反射风险。
- 本机**没有 Android SDK**（无 `ANDROID_HOME`、无 `~/Library/Android/sdk`），所以只能在 CI 构建。

**启动与导航**

- 入口 [MainActivity.kt](../../android/app/src/main/java/tech/loveace/appv3/MainActivity.kt)：`RibbonApp` → `AuthViewModel` → 根据 `AuthState` 决定走登录页或主壳。
- **15 条 `composable<...>` 路由全部写在 MainActivity.kt 内**（约 187–297 行）；[AppNavigation.kt](../../android/app/src/main/java/tech/loveace/appv3/ui/navigation/AppNavigation.kt) 只有 `@Serializable` 路由对象定义（19 个）。AGENTS.md 说「路由在 AppNavigation.kt」只说对了一半。
- 竖屏 [MainShell.kt](../../android/app/src/main/java/tech/loveace/appv3/ui/screen/MainShell.kt) 里有**第二个 NavHost**（4 个 tab：首页/爱安财/更多/我的）。
- 横屏 [LandscapeShell.kt](../../android/app/src/main/java/tech/loveace/appv3/ui/screen/landscape/LandscapeShell.kt) **不用 NavHost**，用 `selectedIndex` + 硬编码 `when` 切页（约 172 行），课程表是魔法下标 4。横屏缺少扫码入口。
- 18 个竖屏 screen（7,248 行）与 16 个 landscape screen（4,677 行）几乎 1:1 重复实现，改一个功能通常要改两处。

**数据层**

- `data/network/`：`AUFEConnection`（登录/重连/心跳）、`HttpClient`（OkHttp 封装 + `peekBody(512)` 嗅探 VPN 登录页 + 默认移动 UA）、`SmartCookieJar`（**纯内存**，进程死了就得重新登录）。
- `data/service/`：12 个 Service，统一返回 `UniResponse<T>`（`success/data/message/error/retryable`）。`retryable` 字段全项目 UI 从不读取，属于死设计。
- `data/model/`：5 个文件、944 行、约 72 个 `data class`，命名沿用上游历史拼写（`coureSequenceNumber`），不要"顺手修正"。
- `data/local/`：`CredentialStore`（EncryptedSharedPreferences）、`ScheduleStore`、`ProfileStore`、`DoorCardStore`、`UpdatePreferences`。
- `data/ble/`：`DoorLockBleManager`、`BleCommandHelper`（门禁蓝牙开锁，Android 独有）。
- 异常处理：data 层有 **71 处 `catch (e: Exception)`，其中 0 处重抛 `CancellationException`**（全 app 也只有 10 处显式重抛），协程取消会被吞掉。

**UI**

- 主题 [Theme.kt](../../android/app/src/main/java/tech/loveace/appv3/ui/theme/Theme.kt) 用 HSL 动态生成色板；[Color.kt](../../android/app/src/main/java/tech/loveace/appv3/ui/theme/Color.kt) 里的 `Ribbon*` 常量是死代码。
- Material3 Expressive + wavy 进度条是既定视觉语言；主壳用了 haze 做玻璃拟态（`haze` 依赖声明了但代码里几乎没用；`biometric` 同样声明未用，`FragmentActivity` 继承是为它留的残迹）。
- 小组件：Glance `SemesterWeekWidget` / `SemesterDayWidget`，`updatePeriodMillis=1800000`（30 分钟），数据由 `WidgetSyncHelper` 写入 `WidgetDataStore`。
- `CourseNotificationService`：课程提醒前台服务。

**测试**：仅 [OtaServiceTest.kt](../../android/app/src/test/java/tech/loveace/appv3/service/OtaServiceTest.kt) 3 个用例（版本比较、manifest v2 解析、SHA-256）+ 2 个模板测试。CI **不跑** `test`/`lint`。

### 4.2 iOS（`ios/`）

**工程**

- 只有 Xcode 工程（`loveaceios.xcodeproj`），两个 target：App `cn.linota.loveace`、Widget `cn.linota.loveace.widget`，Team `2PYK4BY5P6`，iOS 17.0。
- 版本号要同步 **8 处**：`MARKETING_VERSION` 与 `CURRENT_PROJECT_VERSION` 各有 App/Widget × Debug/Release 四份（AGENTS.md 只提了 build 号的 4 处）。
- App Group `group.cn.linota.loveace`；Widget 通过 `Shared/WidgetModels.swift` + `UserDefaults(suiteName:)` 拿数据，**不链接任何共享框架**。
- 唯一 SPM 依赖 SwiftSoup（`scinfu/SwiftSoup`）。本机 `xcodebuild` 因无法访问 GitHub 而卡在包解析（8.1）。
- **新 clone 不能直接编译**：`loveaceios/AnalyticsSecrets.swift` 被 `.gitignore` 忽略，仓库只有不参与编译的 `AnalyticsSecrets.example.swift`；CI 在 [`ios-testflight.yml:43-58`](../../.github/workflows/ios-testflight.yml) 现场生成。本地构建前需自己复制一份并填值（留空也能编译，埋点会静默关闭）。
- 工程用**文件夹同步组**（`PBXFileSystemSynchronizedRootGroup`）绑定 `loveaceios/`，新增 Swift 文件会自动进 target；`Shared/WidgetModels.swift` 在 pbxproj 里有重复 build-file 条目、Products 里有两个 `.appex`，属于工程脏数据（AGENTS.md 说的 duplicate warning 就是它）。
- 没有 shared scheme（`xcshareddata` 不存在），CI 靠 xcodebuild 自动生成；建议补上以免升级 Xcode 后行为变化。
- `Info.plist` 在仓库根 `ios/Info.plist`（不在 `loveaceios/` 内），同时开启 `GENERATE_INFOPLIST_FILE`，手写键与生成键合并；`NSAllowsArbitraryLoads=true` 是内网 http 的无奈之举。

**结构**

- `loveaceiosApp.swift` → `AuthViewModel`（`@MainActor @Observable`）→ `ContentView` 恢复会话 → `MainTabView` 4 个 tab（首页/爱安财/更多/我的）。
- View 20 个文件约 4,864 行（最大 `ScheduleView` 466、`LaborClubView` 455、`ElectricityView` 381）；`Components/DesignSystem.swift` 提供 `glassCard`/`glassInteractiveCard`/`GlassBadge`，新 UI 应复用它。
- Network：`HTTPClient` 是 `actor`，每个客户端独立 `HTTPCookieStorage`；`SessionPageDetector` 统一判定会话过期（比 Android 的嗅探更完善）；`NetworkLogStore`（416 行）记录请求/响应/重定向并支持导出，是**排查学校接口变更的主力工具**（注意：>256 KB 的响应会原样落盘，16 KB 预览未脱敏，分享 ZIP 前要提醒用户）。
- 14 个 Service 文件；`CourseScheduleService` **没有任何 UI 使用**，`JWCService.getTrainingPlanInfo`、`YKTService.getPurchaseHistory` 等为死代码。
- `AnnouncementService` 只解析 manifest v2 的 `schema_version=2` 与 `announcements`（过滤 `expires_at`），**iOS 端没有任何 OTA/版本检查逻辑**，升级只能靠 App Store/TestFlight。

**特色**

- `InsightsView`（230 行，使用统计）与网络日志导出是 iOS 独有。
- `AuthViewModel` 的重连比 Android 细：区分 `.unavailable`（网络不可用，延后重连）与 `.failed`（凭证失效，自动登出），并用 `sessionGeneration` 让 UI 丢弃旧会话的异步结果；代价是重连后 `MainTabView().id(sessionGeneration)` 全量重建，正在填的表单会丢。
- 无测试 target；验证靠 `xcodebuild` + 模拟器手工。

**已知问题（P0/P1 级）**

- **退出登录不彻底**：登录成功即无条件写 "remembered" Keychain，`logout()` 只清 session 副本；下次冷启动 `restoreSession()` 用 `load() ?? loadRemembered()` 自动登录。配合 `LoginView.onAppear` 回填密码，等于"退出"只清内存。
- **Widget 残留上一位用户的课表**：`WidgetDataBridge` 没有 clear，`logout()` 也不碰 App Group；桌面小组件会继续显示旧课表。
- **隐私清单与行为不一致**：`PrivacyInfo.xcprivacy` 声明 `NSPrivacyCollectedDataTypes` 为空，但实际采集设备/系统版本、client id、学号前 4 位、学号加盐 MD5，App Store 审核有被质疑风险。
- **合规灰区**：劳动俱乐部扫码签到在固定坐标附近伪造 GPS（`LaborClubViewModel.scanSignIn`）；自动评教以 80% 概率选最高权重项并随机生成评语后自动提交。这两项需要产品层面确认是否保留。
- 43 处 `connection.client!` 强解包；`ScheduleStore` 只写不读（断网课表是空的）；`ProfileStore` 用私有 suite，数据位置反直觉。

### 4.3 Desktop（`desktop/`，Flutter）

**构建与身份**

- `version: 1.1.12+23`；`pubspec.yaml` 写 Dart `^3.12.2`，但 `pubspec.lock` 已要求 `>=3.13.0-0` 与 Flutter `>=3.44.0`，新机器用旧 SDK 会 `pub get` 失败。
- `fluent_ui` 提供 WinUI 观感，`provider` 做状态，`dio` 做 HTTP，`flutter_secure_storage` 存凭证。
- **三个平台标识必须保持不变**（否则升级链路断）：
  - macOS Bundle ID `cn.linota.loveace.desktop`（`macos/Runner/Configs/AppInfo.xcconfig`、`project.pbxproj`）
  - Windows Inno `AppId={{024BDD87-AACF-4ABF-8B96-DF312AAC2027}`（`windows/inno-ci.iss`）
  - Linux `APPLICATION_ID=io.github.yeningyuan08.LoveACE`（`linux/CMakeLists.txt`、[build-appimage.sh](../../desktop/appimage/build-appimage.sh)）
- Release entitlements **不能**带 `keychain-access-groups`，macOS CI 会硬断言（公证要求）。这是 macOS 端改用本地加密文件存凭证的根因。

**启动与状态**

- [main.dart](../../desktop/lib/main.dart)：**每次启动都 `CacheManager.clear()`**，清掉所有 `cache_*` 缓存（`smart_course_selection_*`、房间绑定、公告 dismiss 不以 `cache_` 开头，不受影响），然后注册 18 个 Provider。
- `WinUIMainShell`（404 行）是常驻侧边栏，12 个页面：首页 / 爱安财 / 学期成绩 / 考试安排 / 自动评教 / 培养方案 / 智能排课 / 竞赛获奖 / 一卡通 / 电费查询 / 劳动俱乐部 / 设置。埋点直接用这个中文数组的下标，新增/重排页面会污染 BI。
- 没有 `window_manager`/`tray_manager`：窗口由三端原生 runner 直接创建（默认 1280×720），没有托盘、没有单实例（Linux 显式 `G_APPLICATION_NON_UNIQUE`）、没有深链、没有窗口状态记忆。
- 状态层是经典 `ChangeNotifier + Provider`：5 个独立 Provider + 13 个依赖登录状态的 `ChangeNotifierProxyProvider`。**每个业务 Provider 各自 new 一个 `JWCService`**，一个进程里有 8 份 JWC 服务/缓存。
- 两个 "电费" 入口后端不同：`ElectricityProvider` 走 ISIM（宿舍电费查询），`YKTProvider` 走一卡通（电费充值）。

**服务层**

- **两个 HTTP 客户端**：`http_client.dart`（1,082 行，带 cookie/重定向/VPN 重登）与 `simple_http_client.dart`（412 行，平铺 cookie + Dio 自动重定向），职责重叠；此外 manifest、analytics、安装器下载各用一个裸 `Dio()`。拦截器代码在 `http_client.dart` 内还重复了两份。
- `RetryHandler` 默认对**所有**异常重试 3 次（含解析/业务错误），会放大风控风险。
- `session_manager.dart` 每 5 分钟检查一次会话；`secure_value_store.dart` 在 macOS/Linux 用本地 AES-GCM 文件（密钥由 salt + 主机名 + 用户名 + home 派生，**只能算混淆，不是真正的密钥保管**），Windows 用 DPAPI。
- 更新：Windows 走「下载安装器 → SHA-256/MD5 校验 → detached 启动」，macOS/Linux 只打开浏览器下载页（[winui_ota_dialog.dart](../../desktop/lib/winui/widgets/winui_ota_dialog.dart)）。强制更新对话框**没有"退出应用"按钮**。
- AppImage 会递归捆绑 `libsecret` 私有依赖闭包（跳过 glib/GTK 等宿主库），因为 `flutter_secure_storage_linux` 仍链接它。

**特色与债务**

- 智能排课：算法 [smart_course_selection_provider.dart](../../desktop/lib/providers/smart_course_selection_provider.dart) 1,424 行 + 页面 3,142 行，是**桌面端独有的核心功能**，也有唯一像样的单测（337 行）。它其实是"全量开课 + 培养方案索引 + 手工模拟选退课 + 冲突检测 + 本地持久化"的交互式规划器，**不是求解/推荐算法**。迁移时必须连同算法和测试一起搬。
- 培养方案页面 2,760 行、一卡通页面 1,462 行、AAC 页面 1,300 行 —— 单文件过大，改动风险高。
- 背景图 + 调色板（`theme_provider.dart` 855 行）是**半成品**：`WinUIBackground` 是 `return child`，设置页没有背景/主色入口，相关 UI 全在无人 import 的 `lib/widgets/` 里。
- 死代码：`lib/widgets/` 14 个文件约 2,100 行零引用；`MoreProvider`、`PinnedFeaturesProvider` 已注册无消费者（`MoreProvider` 的命名路由还是坏链）；`CourseSelectionPreset` 只有模型。
- 测试：`test/manifest_v2_test.dart`（82 行，2 个）+ 智能排课（337 行，5 个）。只覆盖 manifest 解码与"模拟选课持久化"，**没有冲突检测/解析测试**。
- 本机 `dart analyze`：**0 error，11 条 info**（`use_build_context_synchronously`、废弃的 `FormField.value` 等），代码整体健康。

## 5. 发布基础设施

### 5.1 manifest v2（唯一发布真相源）

- 规范定义在 [manifest.py](../../utils/manifest_v2/manifest.py)：`schema_version=2`、`revision`、`announcements[]`、`platforms{android,ios,windows,macos,linux}`、`semester`、`legacy_projection`。
- 公开对象（S3/EdgeOne）：
  - `loveace/manifest_v2.json`（权威清单）
  - `loveace/manifest.json`（由 v2 **派生**的旧版 OTA，老客户端在读，禁止手改）
  - `loveace/download.html` + `loveace/download_page_v2.html`（v2 下载页，部署后两个 key 内容相同）
- 原生包路径固定 `loveace/releases/<platform>/<version>/<build>/<filename>`，host 必须是 `release.loveace.top`，发布器强校验（`manifest.py` 的 `ReleaseArtifact.validate_native_location`）。
- 平台清单里 `releases[0]` 约定为最新（写入时插到索引 0，不按 `published_at` 排序）；`minimum_supported_build` 决定强制更新（客户端判据：`currentBuild < minimum`）。
- 客户端拉取顺序：`https://loveace.linota.cn/loveace/manifest_v2.json` → 回源 `https://release.loveace.top/...`；Android 在 v2 失败时还会退回 legacy `manifest.json`。

**legacy 投影的语义缺口**（老客户端只看 `manifest.json`，出问题时最容易踩）：

| 缺口 | 后果 |
| --- | --- |
| 投影只取 `platforms` 含 `all` 的公告 | 平台定向公告（`--platform android`）老客户端看不到 |
| 投影不过滤 `expires_at` | 过期公告会一直弹给老客户端（v2 页面会过滤） |
| `force_ota` 只在 `minimum == 最新 build` 时为 true | 用 `--minimum-supported-build` 传更小的值时，legacy 端不会强制更新 |
| `ota.content` 取全局最新 release 的 summary | Windows 发版会改掉 Android legacy 弹窗文案 |
| 一个 release 有多个 artifacts 时只投影第一个 | 多架构分发在 legacy 端失效 |

> 结论：**新功能优先信任 v2，legacy 只当作兼容层**；发公告时若希望老客户端也收到，必须用 `--platform all`。

**CLI 子命令**（[cli.py](../../utils/manifest_v2/cli.py)，必须在 `utils/manifest_v2` 目录内跑）：`bootstrap` / `release` / `web-release` / `announce` / `clear-announce` / `notice` / `clear-notice` / `sync-semesters` / `set-force` / `status` / `deploy-page`。其中 `deploy-page` 只被 `deploy-release-metadata.yml` 调用；`announce`、`notice`、`web-release`、`set-force` **没有 CI 入口**，只能本地跑（需要 S3 凭据），也没有并发组保护。

```bash
  -f force=false -f dry_run=false
```

### 5.3 Analytics Worker

- 入口 [src/index.ts](../../analytics-worker/src/index.ts) 1,471 行，路由：`GET /healthz`、`GET /bi/data`、`POST /v1/events`、`POST /admin/maintenance/run`、`GET /bi`（静态 `public/bi.html`）。
- 存储：D1 `loveace-analytics`（事件表 + nonce + 限流 + rollup），R2 `loveace-analytics-archive`（原始事件归档），cron `*/5 * * * *` 做 rollup + 归档。
- 事件白名单 10 个：`app_start / login_success / login_failed / session_expired / session_reconnect_success / session_reconnect_failed / screen_view / feature_action / ota_check / ota_update_click`。
- 签名：`HMAC_SHA256(secret, "<ts>.<nonce>.<sha256hex(body)>")`，时间偏移 ≤300s，nonce 600s 内不可重放。**三端 + 诊断脚本 + 服务端必须同步改**。
- 隐私：客户端上报 `grade_prefix`（学号前 4 位）与 `md5(学号 + salt)`；服务端另存 `sha256(salt:ip)`；BI 只展示聚合；`client_id`、`device_model`、`os_version`、`build`、`user_agent` 也会落库（README 未写明）。
- D1 表：`analytics_events`（原始事件）、`analytics_nonces`（防重放）、`analytics_rate_limits`（固定分钟窗限流，60/min，按 ip/client/student 三键）、`analytics_rollup_counts` + `analytics_rollup_identities` + `analytics_rollup_state`（5 分钟 cron 预聚合）。
- 两个易踩的运维点：
  - `analytics_rollup_state['maintenance:local_backfill']="1"` 会让 cron **整体跳过**维护任务；手工回填时忘了复位，BI 会停在旧数据。
  - `POST /admin/maintenance/run` 支持 `archive_all=true`（清空已 rollup 的原始事件），只靠一个所有客户端都内嵌的 API Key 保护，属于高风险入口。
- 部署：`gh workflow run deploy-analytics-worker.yml --ref main`（顺序：`tsc --noEmit` → R2 bucket → `d1 migrations apply --remote` → `wrangler deploy` → 3 个 `secret put`）。**先 deploy 后写 secret**，首次部署有短暂 503 窗口；D1 没有 down 迁移，`0003` 的 DROP 不可逆。

最常见的 CI 失败原因（按发生概率）：

| 工作流 | 失败点 |
| --- | --- |
| `build-apk` | 输入 `version` 与 `versionName` 不一致（CI 硬校验）；keystore/密码 secret 缺失；产物不叫 `app-release.apk` |

| `build-desktop-linux-appimage` | `appimagetool` 从 GitHub 下载失败；缺 GTK/libsecret 头文件 |
| `deploy-analytics-worker` | `tsc` 严格模式报错；部署成功但 secret 步骤失败（留下新代码 + 旧密钥）；无并发组，两次部署会竞争 |

## 7. 文档与事实的差异

### 7.1 `android/AGENTS.md`

| 说法 | 事实 |
| --- | --- |
| 「Services 由 `AuthViewModel.initServices()` 手动创建」 | 有例外：`DoorCardService` 由 `DoorCardViewModel` 自建；`ISIMService`、`Analytics` 各自 new OkHttp |
| 「复用 `AUFEConnection`/`HttpClient`」 | 有 3 个例外：ISIM、门卡、Analytics |
| 「路由在 `ui/navigation/AppNavigation.kt`」 | 只有路由对象；NavHost 与 15 条注册在 `MainActivity.kt` |
| 「本机没有可用的 Android 构建环境」 | **半对**：JDK 17 已装，Android SDK 确实缺失（无 `ANDROID_HOME` / `local.properties`） |
| 「`clearServices()` 清理服务」 | 不清理 DoorCard/ISIM 内部 client，存在泄漏 |

### 7.2 根 `README.md`

- 版本徽章：Android 1.1.16（实际 1.1.21）；Desktop 1.1.11（实际 1.1.12+23）。
- 「Desktop 覆盖 macOS 与 Windows」：实际还有 Linux AppImage，且 README 正文自己也写了 Linux 一节。
- 未说明 `ios-testflight` 不写清单、`announce` 只能本地跑。

### 7.3 `docs/architecture/kmp-migration-plan.md`

- 作为「现状分析」非常准确（三端重复、事件维度不齐、测试缺失都能对上）；作为「计划」尚未动工——**仓库里没有 `shared/` 模块，也没有根 Gradle 工程**。
- 其中「Android 有 77 处 `catch (e: Exception)`」是旧数字；当前 main 有 121 处（data 层 71 处）。
- 文中「桌面端使用窗口/托盘」是目标形态，现在没有托盘。

### 7.4 Worker README

- 只列了 3 个接口，缺 `/bi/data`、`/admin/maintenance/run`、`/`。
- 声称「只保存 grade_prefix 和加盐 student_hash」，实际还落 `client_id`、`user_agent`、`device_model`、`os_version`、`build`、`ip_hash`（均为匿名/截断后）。

### 7.5 `ios/AGENTS.md`

| 说法 | 事实 |
| --- | --- |
| 只提醒 `CURRENT_PROJECT_VERSION` 有 4 处 | `MARKETING_VERSION` 也有 4 处，版本号一共要同步 **8 处** |
| 「duplicate build-file warning 可能出现，不要清理工程设置」 | 实际是 `WidgetModels.swift` 有重复 PBXBuildFile、Products 里有两个 `.appex`，属于脏数据；不清理也能构建，但升级 Xcode 后可能变成错误 |
| 未提构建前置条件 | 新 clone 缺 `AnalyticsSecrets.swift`（被 gitignore），不复制 example 就编译失败；CI 会现场生成 |
| 「There is no test target」 | 属实 |

### 7.6 桌面端与 README / 文档的差异

- README 徽章 Desktop 1.1.11、实际 1.1.12+23。
- README 说 Desktop 覆盖 macOS/Windows，实际有完整 Linux runner + AppImage + CI。
- README 的 Linux 脚本路径写成 `.desktop/appimage/build-appimage.sh`，实际是 `desktop/appimage/build-appimage.sh`。
- README 功能列表把「报修、门禁、课程表」算作桌面端能力，桌面端实际**没有**报修/门禁/独立课表页（课表只在智能排课网格里）。
- 桌面端用户协议写 "GNU AGPL-3.0 + 禁止商业使用"，而仓库 LICENSE/NOTICE/README 是 Apache-2.0，**互相矛盾**。
- 用户协议称 macOS 用 Keychain，实际 macOS/Linux 都用 app-local AES-GCM 文件。
- `docs/architecture/kmp-migration-plan.md` 把「背景图与调色板设置」列为桌面独有功能，实际背景是 no-op、调色板 UI 不可达。
