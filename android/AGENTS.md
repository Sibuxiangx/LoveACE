# AGENTS.md

## Build and verification

- This machine does **not** have a usable Android build environment. Do not rely on local `./gradlew assemble*`; validate syntax/whitespace locally with `git diff --check`, then use GitHub Actions for real builds.
- CI/release workflow: `.github/workflows/build-apk.yml`. It is **manual only** (`workflow_dispatch`), installs JDK 17 + Android SDK 36, restores signing secrets, builds the release APK, uploads the artifact, then publishes it through `utils/manifest_v2` with `uv run python cli.py release ...`.
- Trigger Android release manually with inputs, for example:
  `gh workflow run build-apk.yml --ref main -f version=1.1.11 -f changelog="更新内容" -f content="发现新版本" -f force=false`.
- Check/watch/download CI artifacts:
  - `gh run list --workflow build-apk.yml --branch main --limit 5`
  - `gh run watch <run-id> --exit-status`
  - `gh run download <run-id> -p 'LoveACE-*' -D <dir>`
- `build-apk.yml` supports `dry_run=true`: builds and uploads the APK artifact but skips the `publish` job entirely. Use it to validate compilation before a real release.
- APK/artifact name: `LoveACE-<version>-<build>-<sha7>-<yyyymmdd-HHMM>[-dryrun]` (Asia/Shanghai time). The build job renames `app-release.apk` before upload. The publish job restores `app-release.apk` before calling the CLI, so the S3 object key and release URL stay the same.
- `setup-android@v3` must pin `packages: platform-tools` (the workflow does): the default value still references the retired `tools` package, which fails on runners with cmdline-tools 16+. GitHub also migrates `ubuntu-latest` between major OS versions; pin `ubuntu-24.04` if a runner image change breaks setup steps.
- Debug APKs are signed with the runner debug key and will not install over release builds. Release APKs are signed in GitHub Actions from repository secrets; do not commit keystores or signing passwords.

## Versioning and release

- Android version lives in `app/build.gradle.kts`. Keep `versionCode = major * 10000 + minor * 100 + patch` (for example `1.1.10 -> 10110`).
- Publishing is part of the manual GitHub Actions workflow after a successful release build. The workflow validates the requested version against Gradle, reads `versionCode`, then runs `cd utils/manifest_v2 && uv run python cli.py release --version <x.y.z> --build <versionCode> --platform android --file <release-apk> --content "..." --changelog "..."`.
- `utils/manifest_v2` reads S3/CDN credentials from environment variables in GitHub Actions secrets. For local one-off publishing it can still read `.env` (ignored). Do not print or commit credentials.
- The publish CLI uploads APKs to `loveace/releases/<platform>/<version>/<build>/...`, computes SHA-256 and compatibility MD5, updates canonical `loveace/manifest_v2.json`, and generates the legacy OTA projection; check with `uv run python cli.py status` from `utils/manifest_v2`.

## App wiring

- Single Android module: `:app`; package root is `tech.loveace.appv3`.
- Compose entrypoint is `MainActivity.kt` / `RibbonApp`. Type-safe routes are in `ui/navigation/AppNavigation.kt`.
- Portrait bottom-nav shell is `ui/screen/MainShell.kt`; landscape navigation is `ui/screen/landscape/LandscapeShell.kt`. User-facing features that belong in “More/教务服务” usually need both portrait and landscape entry points.
- Landscape nav items are mapped by array index in `LandscapeShell`'s `when (selectedIndex)`. Inserting or removing an item means shifting every index after it in the same edit (for example “开课查询” is index 5, “空闲教室” is 6, “门禁查询” is 11, “我的借阅” is 12, “零星维修” is 13, “竞赛信息” is 14, “劳动俱乐部” is 15, “我的” is 16). The 16 branch shows `MailPasswordScreen` in place of settings while `mailPasswordOpen` is set, and the settings screen opens it from its 账号 row.
- Services are manually created in `AuthViewModel.initServices()` and cleared in `clearServices()`. New authenticated features normally add a `data/service/*Service`, `ui/viewmodel/*ViewModel`, screen(s), route, and an `AuthViewModel` service property.

## Network/session conventions

- Reuse `AUFEConnection` and its shared `HttpClient`/`SmartCookieJar`; do not implement a parallel login flow for school services.
- Login is two-stage: VPN EC login, then UAAP/CAS login. `AuthViewModel` wires session-expiry detection and auto-reconnect.
- Forced password change interception: CAS may 302 to `/mng/acp/completeInfo/password` after the TGT is issued (password is correct). `AUFEConnection.performUaapLogin` maps this to `UAAPLoginStatus(failPasswordChangeRequired)`; treat it as a non-error state — never clear credentials, never count it as a login failure, never auto-retry (reconnect() records it in `lastUaapPasswordChangeRequired` and `AuthViewModel` stops reconnecting).
- Captcha (EC gateway): when the auth page has `<RndImg>1</RndImg>`, or `login_psw.csp` answers 20041, the password is not submitted. `AUFEConnection.ecLogin(captchaCode)` returns `failCaptchaRequired` with `captchaImage` (GET `/por/rand_code.csp` with `Cookie: TWFID=<same auth page>`). The pending auth context (TWFID/CSRF/RSA) is in memory, single-use, valid 180 s, and reused by the code POST. `failCaptchaInvalid` (20023) counts as a failure and triggers a fresh challenge. Never log the code, the image, or the context.
- Login throttle: `AuthViewModel` counts `failInvalidCredentials` and `failCaptchaInvalid`. Cooldown ladder is 0 / 30 s / 120 s / 600 s (`loginCooldownMillis`), stored in SharedPreferences `login_throttle` (`failures_<userId>`, `cooldown_until_<userId>`) and cleared on success. Network errors and captcha prompts do not count.
- The captcha-waiting state uses `AuthState.Initial`, not `Error` or `Unauthenticated`: `MainActivity` navigates on those states and would reset the typed input. Auto-reconnect and session restore that need a captcha keep saved credentials and show "学校要求输入验证码，请重新登录".
- The login form must not be rebuilt while logging in or after a failed login. `MainActivity` navigates to `LoginRoute` on `Unauthenticated`/`Error` only when it is not already there (`hasRoute`); rebuilding the screen resets typed input and re-prefills remembered credentials. On a wrong school/VPN password, `AuthUiState.passwordInvalid` makes the login form clear the two password fields and keep the userId.
- Weak school password hint (`util/TextValidation.kt` `isWeakSchoolPassword`): 6 digits, or 5 digits plus 1 ASCII letter at the end. The manual login form shows `WeakPasswordDialog` before submitting; "继续登录" submits anyway. Hint only; never blocks login. Quick login and auto-reconnect skip the check. The dialog lives in `LoginScreen.kt` and is reused by the landscape login.
- The gateway-password option (former 高级选项) was removed. Login uses one password (教务密码) for both school and gateway, so there is no separate VPN password field, switch, or advanced confirm dialog. The "加入交流群" entry card sits under the login button in both login views and the "我的" page has a matching row; both open the group popup.
- `HttpClient` only supplies a default mobile UA when a request did not set `User-Agent`; service-specific UA headers are intentional.
- Login diagnostics (`diagnostics/LoginDiagnostics.kt`, `LoginLogCompressor.kt`, `DiagnosticsExport.kt`, `DiagnosticsUploader.kt`, UI in `ui/screen/LoginDiagnosticsUpload.kt`; mirrors iOS `LoginDiagnostics.swift` function by function): the last 10 login attempts are kept as PCL-style lines `[HH:mm:ss.SSS] [LEVEL] [MODULE] text` (max 300 steps each) in `filesDir/login_diagnostics/attempts.json`. `HttpClient.execute` feeds one `HttpRecord` per round trip only while an attempt is active; `AuthViewModel.login` begins/finishes attempts (user-initiated only, not restore/reconnect/cooldown taps) and notes EC/UAAP presence flags. Privacy: every hidden value is written as a code `<PascalCase>` built from its key (`<Password>`, `<SetCookie>`), never the value; URLs keep only the service and first two path segments; response bodies are never stored (only a masked 800-char excerpt, and binary responses record only their size). When login has failed, both login screens show a small text link 「分享登录诊断」 under 「不知道密码是什么？」. Tapping it opens the consent dialog with the real attempt count N. Confirming runs `AuthViewModel.uploadLoginDiagnostics`, which exports schema `loveace.login-diagnostics/v1` (sorted keys, contract keys only, contract outcome strings) and POSTs it to `https://analyst-api.loveace.top/v1/diagnostics` through `DiagnosticsUploader` on `Dispatchers.IO`. The signature reuses `Analytics.sha256`/`hmacSha256` with the existing `ANALYTICS_API_KEY` and `ANALYTICS_SIGNING_SECRET`. Success opens a result sheet with the selectable `diag.html` URL, a copy-link button, and a 「加入用户群」 button that reuses `QqGroupService`/`QqGroupPopup`. Failures show an inline message mapped from the server error code.
- JWC endpoints use the VPN host `http://jwcxk2-aufe-edu-cn.vpn2.aufe.edu.cn:8118`; keep historical field spellings from upstream APIs, including `coureSequenceNumber`.
- 开课查询（`CourseScheduleService.queryPage` + `CourseScheduleViewModel`，`ui/screen/CourseSchedule*.kt`）与 iOS 同一结构：右上角“筛选”打开条件 sheet（`CourseFilterSheet`），草稿在 sheet 里编辑，点“查询”才生效（`CourseScheduleUiState.applied`）；空状态引导点右上角。结果是分页列表，`courseInfo` 的 `PAGE_SIZE = 20`，接近末尾才加载下一页，不要一次拉取整个学期。学期列表与下拉选项来自同一个 `courseSchdule/index` 页面；页面没有某个维度的 `select` 时该下拉隐藏。记录按 `courseRecordKey` 跨页去重。横屏与竖屏共用 `CourseScheduleScaffold`。
- 空闲教室（`FreeClassroomService` + `FreeClassroomViewModel`，`ui/screen/FreeClassroom*.kt`）与 iOS 同一流程：时段（教学周、星期、节次多选）→ 范围（可不选）→ 查询。查询先取所选时段的空闲教室 `freeClassroomQuery/search`：未选校区时西校（2）、东校（1）各查一次，`weeks` 与 `wSection`（`weekday/section`，逗号分隔）必须非空，空值结果不可靠；再用 `classroomCurriculum/{campus}/{building}/classroomJson` 枚举范围内每栋楼的全部教室（不要用无条件查询，它会漏掉通慧楼等教学楼），按楼缓存在 VM 中，最多 4 栋并发。结果直接按楼、楼层展示全部教室并标出空闲或占用，没有楼详情页。占用来自详情页隐藏域 `wsSection`（`weekday_week_section`）。停用规则：教学楼备注或名称含“停用”的楼默认隐藏；房间名含“停用”的教室始终显示并带标记；状态码 `02` 或 `03` 的教室默认隐藏，打开“显示停用教室”后显示并带标记；名称含“虚拟”或座位数超过 1000 的记录不是实体教室，直接剔除；同一楼宇、同一房号的多行合并为一间。楼层为推测：三位数取首位，四位数取前两位，超过 12 层归入“其他”。切换“显示停用教室”时已有结果会自动重查。
- 空闲教室横屏与竖屏共用 `freeClassroomControlItems` / `freeClassroomResultItems`（`ui/screen/FreeClassroomScreen.kt`）：横屏左侧为时段与范围，右侧为结果。改任一处时两边都要检查。
- Auto teacher evaluation (`TeacherEvaluationService`/`TeacherEvaluationViewModel`): no first-visit gate or countdown; `isFirstVisit` is per browser session, not per account, so it must not gate loading, searching, or submitting. Each course fetches a fresh index token in `prepareEvaluation` (no batch snapshot). Read requests (index, search, evaluationPage) retry on network errors; `assessment` never retries. An unconfirmed submit is verified first; if verification fails the course becomes `verifyUnknown` and is never resubmitted. Only `prepareFailed`/`submitFailed` courses get the single post-batch compensation round, after a successful course-list refresh. A VPN login page maps to "会话已失效，请重新登录". The batch is ViewModel-scoped: leaving the screen does not cancel it, `load()` is a no-op while running, and `currentService()` picks up a reconnected service. Desktop follows the same rules (provider-scoped batch, `RetryHandler` for reads); iOS cancels the batch on leave instead (see `ios/AGENTS.md`).

## Portal (学校门户)

- `data/service/PortalService.kt` is the only portal entry point; models are in `data/model/PortalModels.kt`. It mirrors `ios/loveaceios/Service/PortalService.swift`, which is the reference. Features: 门禁记录 (`AccessRecordsScreen`), 我的借阅 (`BorrowingScreen`), 企业邮箱初始密码 (`MailPasswordScreen`, portrait Settings → 账号 and the landscape settings page), and 一卡通消费记录 (`YKTViewModel` reads consumption from the portal; the balance still comes from ykt).
- Session: `PortalService` walks the CAS entry by hand on `connection.noRedirectClient` (up to 10 hops, 301–308 with `Location`, each hop mapped to the VPN host), then sends one `GET /sf-webproxy/api/vpn-config` (result ignored), then `POST /api/portal/homepage/hpdata`. Setup is single-flight through a `Mutex` plus a shared `CompletableDeferred`, and failures are not cached. `hrmResourceID` is cleared on session-expired.
- Request shape: every portal API URL carries `?sf_request_type=fetch`, with `X-Requested-With`, `Referer: <base>/spa/portal/static/index.html`, and `sdp-app-session` (`AUFEConnection.twfId`). Keep all of these; they match the browser capture.
- Interception: hpdata answering 404 with `Errormsg: securityIntercept` starts a 180 s cooldown, and the user-facing text says to fully quit and reopen the app. Do not retry during the cooldown. The cooldown is checked after the cached-session check.
- Cube reads: `getList` → `counts` → `datas`. The data key must be 32 characters. Fields are matched by column title, then `dbField`, never by index. Cubes: dorm access 37501 (date field 178950), library access 71001 (date field 316587), borrowing current 84509 and history 84510, consumption 74507 (date field 299018, 本月 code `3`, 100 rows per page), mail initial password 82510. Access pages are 10 rows; dorm range codes are 1/9/2/3/0 and library week is `2,,`.
- Logging: portal code logs the step, status, host and path only. Never log bodies (the mail password is in a `datas` body), cookies, TWFID or passwords.
- The mail initial password is memory-only: it lives in `MailPasswordViewModel` state, is cleared when the screen is left, and the copy is flagged `EXTRA_IS_SENSITIVE`. The clipboard is cleared 60 s later only if it still holds the same text (best effort; on Android 10+ a background app may not be able to read the clip, and then the clear is skipped).
- ViewModels drop stale results with a generation counter. A refresh failure keeps the loaded data and shows the error with a retry; only a first-load failure replaces the content with the error state. These rules came from iOS, where the mail and borrowing screens had the gaps.
- `CredentialStore` reads never clear saved credentials on failure. A locked or unavailable keystore must not sign the user out.
- Known gap: the `CredentialStore` constructor (MasterKey and EncryptedSharedPreferences setup) is not guarded and can still throw at app start.

## Remote config

- `service/RemoteManifestService.kt` fetches `loveace/manifest_v2.json` (EdgeOne `loveace.linota.cn` first, `release.loveace.top` fallback) with `ignoreUnknownKeys`; unknown top-level fields are safe to add.
- OTA/update dialogs and announcements flow through `OtaService`/`OtaViewModel` (checked silently at app launch, before login).
- `prelogin_notice` is the pre-login banner rendered by `ui/screen/PreloginNoticeCard.kt` inside both login screens; fetch failures must stay silent and never block login. Publish/clear it via the `deploy-release-metadata.yml` workflow (`publish-prelogin` / `clear-prelogin`).
- Group entry source: `service/QqGroupService.kt` fetches the independent `loveace/qq_group_v1.json` (`loveace.linota.cn` first, `release.loveace.top` fallback), separate from `manifest_v2`. Entries render only when the fetch succeeds, `schema_version == 1`, and `enabled == true`; otherwise nothing is shown. Components live in `ui/components/QqGroupComponents.kt`.

## UI conventions

- The app uses Compose Material3 Expressive (`androidx.compose.material3` 1.4.0). Loading uses the self-drawn flower loader `RibbonShapeLoader` through `AppCircularProgressIndicator`; Material3 1.4.0 has no `CircularWavyProgressIndicator` / `LinearWavyProgressIndicator`. Prefer these over introducing a different visual language.
- Keep changes surgical: many screens have separate portrait and landscape implementations; update both only when the feature is exposed in both modes.
- 节次、星期、教学周选择器是 `ui/md3e/RibbonSelector.kt` 的 `RibbonSlotGrid`（选项格，选中时圆角 spring 变形为胶囊）与 `RibbonWeekStrip`（周次横向条）。Material3 1.4.0 的公开 API 里没有 `ButtonGroup`、`ToggleButton`、`LoadingIndicator`，`ExperimentalMaterial3ExpressiveApi` 也是 internal，不要引用它们；Expressive 效果用 md3e 组件和 spring 变形实现。
- 桌面课程小部件（`widget/SemesterDayWidget.kt`、`widget/SemesterWeekWidget.kt`）不要用 `LazyColumn`：在 HyperOS 4 / Android 17 上 RemoteViews 集合不渲染，课程块整体空白，但数据读取和更新投递都正常。课程内容量很小（周网格 ≤12 节、日列表 ≤10 门），用普通 `Column` + `forEach`。改小部件后要在真机上确认。
- Exams and semester state (`widget/SemesterWidgetData.kt` `resolveSemesterPhase`, mirrored by `SemesterViewModel`): exams come from `JWCService.getExamInfo` and are cached in `widget_cache/exams.json` (`WidgetExamSnapshot`, defaulted fields; missing file = no exams). Teaching end = start + weeks×7 days. Exams inside the teaching period (including week-18 weekend days) become course entries on their date and do not change the week label. After teaching end, any exam dated today or later makes the state `ExamWeek` (home "考试周", widget exam card); with no such exam it is vacation. The course widgets and the persistent notification treat exams as items: the next-item slot is the earliest item whose end is still in the future. Exams never trigger the 课前提醒 push. Prefetch: `MainActivity` calls `WidgetSyncHelper.syncWidgetData` on Authenticated and on every resume, with no throttle, in a background coroutine; a failed fetch keeps the previous snapshot, and `SemesterViewModel` recomputes from cache when `WidgetSyncHelper.snapshotVersion` changes.
